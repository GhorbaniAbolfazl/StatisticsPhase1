## دریافت، منبع و بازسازی

منبع مستقیم، سه فایل آموزشی تحویلی تیم دستیاری است. تاریخ دریافت به نقل از دانشجو ۱۰ اکتبر است؛ سال دریافت، دورهٔ استخراج، نسخهٔ آماده‌سازی، روش جایگذاری و پرچم‌های آن در اطلاعات موجود مشخص نیستند. مستندات رسمی [UDS](https://files.alz.washington.edu/documentation/uds3-rdd.pdf) و [MRI](https://files.alz.washington.edu/documentation/SCAN-MRI-Imaging-RDD.pdf) برای تعریف متغیرها استفاده می‌شوند و جای نسخهٔ آموزشی تحویلی را نمی‌گیرند.

سه CSV اولیه در پوشهٔ محلی data باقی می‌مانند. طبق صفحات ۱۸ و ۱۹ [فایل درس](../docs/amarpr.pdf#page=18)، بستهٔ ZIP تحویل و فایل‌های قابل ثبت در Git به‌صورت پیش‌فرض شامل دادهٔ خام نیستند. گیرنده برای بازتولید باید همین سه فایل TA را با همین نام‌ها در data قرار دهد؛ اثر انگشت آن‌ها پیش از محاسبه بررسی می‌شود. جدول منتخب مشتق، کد، قواعد و خروجی‌ها همراه بسته‌اند.

## جدول مشتق و دامنهٔ آن

[phase1_participants.csv](processed/phase1_participants.csv) یک جدول مرجع با **۱۲۳۷ ردیف و ۴۵ ستون** است: هر شناسهٔ مشترک دقیقاً یک ردیف دارد. اتصال یک‌به‌یک با `NACCID` انجام می‌شود؛ ترتیب ردیف‌ها مبنای تطبیق نیست. در این ورودی شناسهٔ مختص UDS یا مختص MRI وجود ندارد. نسخهٔ کاری `NACCUDSD` از UDS می‌آید و ابتدا برابری عددی با MRI برای هر فرد کنترل می‌شود؛ متن خام هر دو باقی می‌ماند.

این جدول فقط متغیرهای منتخب و اطلاعات ردگیری/کیفیت را دارد؛ جایگزین ممیزی هر ۳۰۶ ستون دو فایل اولیه نیست. سه فایل اصلی لازم باقی می‌مانند. همهٔ ۱۲۳۷ فرد در جدول‌اند؛ انتخاب خروجی به پرچم همان خروجی وابسته است.

| شناسهٔ مجموعه | شرط | تعداد |
|---|---|---:|
| `main_pair` | پاسخ اصلی و میانگین ضخامت قابل استفاده | ۱۲۲۸ |
| `main_common` | زوج اصلی به‌اضافهٔ سن، جنس و تحصیلات قابل استفاده | ۱۲۲۶ |
| `integer_pair` | زوج اصلی با MoCA صحیح‌مقدار | ۹۸۴ |
| `integer_common` | زوج حساسیت به‌اضافهٔ هر سه متغیر همراه | ۹۸۲ |

این مجموعه‌ها هم‌پوشانی دارند و جمعشان حجم نمونه نیست. برای مقایسهٔ مدل‌های فازهای بعد باید از پاسخ و نمونهٔ مشترک یکسان استفاده شود؛ هنوز مدلی برازش نشده است. برای توصیف هر متغیر، می‌توان تمام مقادیر کاریِ قابل استفادهٔ همان متغیر را با مخرج صریح گزارش کرد. تحصیلات نامعلوم فرد را از توصیف MoCA حذف نمی‌کند.

## قرارداد ذخیره و خواندن

- فایل UTF-8 با جداکنندهٔ ویرگول و یک ردیف سرستون است. مقادیر خام رشته‌اند؛ از تبدیل خودکار آن‌ها به عدد اجتناب می‌شود تا تفاوت نوشتاری متن اولیه از بین نرود.
- نوع ذخیره در [phase1_manifest.json](processed/phase1_manifest.json) برای تک‌تک ستون‌ها تعریف شده است. `number` فقط نوع حمل داده است؛ جنس و وضعیت شناختی همچنان متغیرهای طبقه‌ای‌اند.
- پرچم‌ها دقیقاً `1` برای درست و `0` برای نادرست هستند؛ رشتهٔ `"0"` را با تبدیل سادهٔ `bool()` نخوانید، چون `bool("0")` در Python برابر True است.
- خانهٔ خالی در متغیر کاریِ nullable یعنی مقدار قابل استفاده موجود نیست. IQR خالی یعنی بررسی نشده، نه نبود دورافتادگی. صفر مشاهده‌شده، مقدار ناموجود و False از هم جدا هستند.
- ستون‌های `*_DETAIL` خالی یعنی توضیح تکمیلی ندارد. ستون علت عدم عضویتِ خالی یک رشتهٔ خالی است و یعنی فرد برای آن خروجی قابل استفاده است؛ ناموجودی پاسخ تلقی نمی‌شود.
- مقدارهای کاری بدون گردکردن تحلیلی، برش به سقف یا جایگذاری دوباره ذخیره می‌شوند. نویسندهٔ پروژه بازخوانی کامل و برابری همهٔ مقدارها، رشته‌ها، پرچم‌ها و ناموجودی‌ها را کنترل می‌کند.
- پرچم IQR از تمام مقدارهای کاریِ قابل بررسی همان متغیر در جدول مرجع محاسبه شده است، نه از هر زیرنمونه به‌طور جدا. پرچم فقط برای مرور است و هیچ‌یک از چهار پرچم عضویت را بر اساس خود تغییر نمی‌دهد.
- ستون‌های خط منبع به CSVهای اولیهٔ بدون تغییر اشاره می‌کنند؛ بررسی ورودی تأیید کرده هر رکورد این فایل‌ها یک خط فیزیکی است. خط با موقعیت فرد پس از فیلتر یا مرتب‌سازی یکسان فرض نمی‌شود.

برای بارگذاری با نوع و کنترل اثر انگشت، از ریشهٔ پروژه:

```python
from pathlib import Path
from src.phase1_dataset import load_dataset

rows, manifest = load_dataset(Path.cwd())
main_common = [row for row in rows if row["MAIN_COMMON_SAMPLE_ELIGIBLE"]]
```

خواننده ابتدا اثر انگشت خروجی‌ها، ورودی‌ها، کد و قواعد و سپس تعداد و شناسه‌های اعضای هر مجموعه را کنترل می‌کند. در صورت تغییر کد یا قواعد، خروجی باید بازتولید شود. برای خواندن دستی CSV، `NACCID` و ستون‌های خام حتماً رشته بمانند؛ تبدیل پیش‌فرض نوع و ناموجودی جای قرارداد پروژه را نمی‌گیرد.

## تصمیم‌ها و حدود تفسیر

- ۲۴۴ MoCA اعشاری داخل دامنه طبق انتخاب کاربر در پاسخ اصلی حفظ و علامت‌گذاری شده‌اند. صحیح‌بودن نمره اصالت آن را ثابت نمی‌کند؛ سناریوی حساسیت هم فقط همین قید عددی را دارد.
- چهار کد MoCA=88 و پنج مقدار دیگر بالاتر از ۳۰ در پاسخ کاری ناموجودند. دو EDUC=99 در تحصیلات کاری ناموجودند؛ خام و علت باقی می‌مانند. شمار و درصد با مخرج هر متغیر در گزارش جریان آمده است.
- میانگین ضخامت فقط از دو طرف قابل استفادهٔ همان شناسه ساخته می‌شود. واحد mm است؛ حجم قشر وارد این فرمول نیست. فقدان یک طرف با طرف دیگر پر نمی‌شود.
- `NACCUDSD` وضعیت شناختی است؛ کد دمانس به‌تنهایی تشخیص علت اختصاصی آلزایمر نیست. گروه هفت‌نفره حفظ شده است.
- نبود فرد فاقد MRI، مقایسهٔ افراد دارای/فاقد MRI را ناممکن می‌کند. تطبیق زمانی مراجعه و اسکن، استقلال مراکز/خانواده‌ها، QC و گمشدگی پیش از جایگذاری از اطلاعات فعلی بازیابی نشده‌اند.

جمع‌بندی در [سؤال و محدودیت‌ها](../reports/phase1/conclusion.md) ثبت شده است؛ تعریف متغیرها، اعضای مجموعه‌ها و دادهٔ مرجع تغییر نکرده‌اند. دامنهٔ ادعا به مقادیر کاری همین زیرمجموعه محدود است و نتیجهٔ رابطهٔ فردی/تعدیل‌شده هنوز برآورد نشده است.

روش اجرای کامل قابل حمل و نقش فایل‌های همراه در [راهنمای بررسی مدارک](../docs/PHASE1_DELIVERY.md) و [README ریشه](../README.md) آمده است؛ فرمان `python3 scripts/run_phase1_notebook.py` از ریشهٔ پروژه همهٔ خروجی‌های محاسباتی و شکل‌ها را همراه نوت‌بوک بازتولید می‌کند. فایل‌های موقت گفتگو برای اجرا لازم نیستند.
