# راهنمای بررسی و تحویل فاز یک - مسیر ج NACC

تاریخ بازبینی: ۲۰۲۶-۱۱-۰۳. این نسخه شامل گزارش فارسی، نوت‌بوک با خروجی ذخیره‌شده، کد، جدول‌ها، شکل‌ها و آزمون‌های قابل اجراست. نتیجهٔ کنترل‌های نهایی و موارد نیازمند اقدام بیرون از پروژه در [گزارش تطبیق نهایی](PHASE1_FINAL_CHECK.md) ثبت می‌شود. آماده‌بودن فایل‌های محلی به معنی ثبت موضوع یا ارسال در GitHub/CW نیست.

## مسیر خواندن

1. [گزارش فارسی](../reports/phase1.pdf): سؤال، طراحی، کیفیت، جریان نمونه، جدول‌ها، چهار شکل، محدودیت‌ها و ادامه؛ دارای فهرست پیونددار و نشانک بخش‌ها.
2. [نوت‌بوک](../notebooks/phase1.ipynb): متن، کد، جدول‌های تفصیلی و همان چهار تصویر؛ برای خواندن خروجی‌های موجود اجرای دوباره لازم نیست.
3. [کارت پروژه](../PROJECT_CARD.md): سؤال و فرضیهٔ علمی اولیه، واحد مشاهده، متغیرها، شاخص و برنامهٔ ادامه.
4. جزئیات: [نقشهٔ داده](DATA_MAP.md)، [فرهنگ متغیرها](SELECTED_VARIABLES.md)، [قواعد کیفیت](QUALITY_RULES.md) و [راهنمای داده](../data/README.md).
5. خروجی‌های مستقل: [ممیزی](../reports/phase1/quality_audit.md)، [جریان](../reports/phase1/sample_flow.md)، [توصیف](../reports/phase1/descriptive_statistics.md)، [شکل‌ها](../reports/phase1/figures.md) و [جمع‌بندی](../reports/phase1/conclusion.md).

## شمارها و قرارداد خروجی

| مورد | مقدار |
|---|---:|
| UDS / MRI | ۱۲۳۷ ردیف؛ ۱۸۰ / ۱۲۶ ستون |
| جدول مرجع | ۱۲۳۷ فرد × ۴۵ ستون |
| زوج اصلی / مشترک اصلی | ۱۲۲۸ / ۱۲۲۶ |
| زوج حساسیت / مشترک حساسیت | ۹۸۴ / ۹۸۲ |
| خلاصهٔ کمی / طبقه‌ای / فراوانی دقیق | ۵۴ / ۵۲ / ۱۴۰ ردیف |

مجموعه‌ها هم‌پوشان‌اند و جمع نمی‌شوند. مقدار خام، صفر، ناموجود و بررسی‌نشده تفکیک می‌شوند. جزئیات نوع، مخرج و پرچم‌ها در [راهنمای داده](../data/README.md) و [شناسنامه](../data/processed/phase1_manifest.json) آمده است.

## بازتولید و کنترل

با Python 3.11 یا جدیدتر، از ریشهٔ پروژه:

```bash
python3 -m pip install -r requirements.txt
python3 scripts/run_phase1_notebook.py
python3 -m unittest discover -s tests -v
python3 scripts/package_phase1.py --check-root .
```

اجرای کامل از همان Python یک هستهٔ موقت می‌سازد، همهٔ سلول‌ها را به ترتیب اجرا می‌کند و نوت‌بوک، گزارش‌ها، شکل‌ها و PDF را تازه می‌کند. خطا یا خروجی stderr مانع ذخیرهٔ نوت‌بوک موفق جدید است. اجرای مرحله‌ای به‌تنهایی تصاویر ذخیره‌شدهٔ نوت‌بوک را تازه نمی‌کند؛ اگر تصاویر ناهماهنگ باشند، ساخت PDF و بسته متوقف می‌شود. آزمون‌ها واقعاً در پوشهٔ tests موجودند؛ نتیجهٔ اجرای فعلی در گزارش تطبیق ثبت می‌شود.

## بستهٔ تحویل و دادهٔ خام

طبق [صفحات ۱۸ و ۱۹ فایل درس](amarpr.pdf#page=18)، دادهٔ خام به‌صورت پیش‌فرض وارد Git یا ZIP نمی‌شود. [فهرست فایل‌ها](../config/phase1_delivery_files.json) نقش هر فایل را مشخص می‌کند؛ سه CSV با `archive=false` محلی و لازم برای بازتولیدند. گیرنده باید همان فایل‌های آموزشی TA را در data قرار دهد. فایل‌های موقت، IDE، محیط مجازی و حافظهٔ نهان وارد بسته نمی‌شوند.

```bash
python3 scripts/package_phase1.py --reproduce
```

این دستور ZIP و اثر انگشت آن را در dist می‌سازد، فایل‌ها و پیوندها را کنترل می‌کند و اجرای کامل و آزمون‌ها را در کپی موقت استخراج‌شده تکرار می‌کند. برای بررسی ZIP موجود:

```bash
python3 scripts/package_phase1.py --verify dist/phase-1-nacc.zip --reproduce --data-root .
```

نسخهٔ محلی سه CSV دست‌نخورده می‌ماند؛ فقط کپی‌های موقت با اثر انگشت یکسان برای کنترل ZIP استفاده می‌شوند. ثبت Git، تاریخچهٔ معنادار تغییرات، برچسب phase-1، انتشار GitHub و بارگذاری CW اقدامات جداگانه‌اند و در این بررسی انجام‌شده تلقی نمی‌شوند.
